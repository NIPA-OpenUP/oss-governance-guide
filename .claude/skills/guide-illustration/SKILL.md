# Guide Illustration — 삽화 기획·생성·배치

「기업 오픈소스 거버넌스 가이드」의 삽화를 만든다. 기획(무엇을 그릴지)과 생산(실제 생성)을 분리하며, 생산 단계에서 프롬프트를 재해석하지 않는 것이 화풍 통일의 전제다.

## 삽화를 만들지 않을 때

먼저 만들지 않을 판단을 한다. 정보 없는 장식 이미지는 문서를 무겁게만 만든다.

각 삽화 후보에 **"이 그림이 없으면 독자가 무엇을 이해하지 못하는가"**를 답한다. 답할 수 없으면 목록에서 뺀다. 시각화 이득이 실제로 있는 것은 다음 다섯 유형이다.

| 유형 | 그림이 필요한 이유 | 구도 |
|------|------------------|------|
| `process` | 단계 순서와 분기를 산문으로 읽으면 위치를 잃는다 | 좌→우 단계 흐름, 번호 표기 |
| `structure` | 계층·포함 관계는 중첩 문장으로 표현하면 깊이가 안 보인다 | 계층 박스, 위→아래 |
| `relationship` | 다자 간 관계는 문장으로 쓰면 조합 수만큼 문장이 늘어난다 | 노드-연결선 |
| `comparison` | 두 대안의 차이는 나란히 놓아야 보인다 | 좌우 2열 대칭 |
| `timeline` | 시행 일정·발전 과정은 시간 축이 있어야 간격이 보인다 | 수평 축, 눈금 표시 |

추상 개념("오픈소스의 중요성")은 이 다섯에 들지 않는다. 억지 시각화 대상이다.

## 한글 라벨을 넣는다

**한글 라벨을 넣어라.** 2026-08 codex-cli 0.145.0 기준으로 삽화 24장을 생성해 전수 확인한 결과, 깨진 음절이 한 건도 없었다. 과거의 '한글 회피' 지침(`none` / `latin-only` / `numbers-only` 전략)은 폐기한다.

라벨 없는 도해는 두 가지 대가를 치른다. 첫째, 독자가 그림과 본문을 대조하며 라벨을 머릿속에서 대입해야 한다. 둘째, **그림과 본문의 불일치가 눈에 보이지 않는다.** 실제로 라벨을 넣는 과정에서 라이선스 스펙트럼이 본문의 4구간 중 3개만 담고 있었다는 것과, AI 3중 검사의 세 게이트 이름이 본문과 전혀 달랐다는 것이 드러났다. 숫자만 있을 때는 둘 다 통과했다.

프롬프트에 다음 지시를 반드시 포함한다.

```
TEXT REQUIREMENT: this diagram carries Korean text labels and the labels are the point
of the diagram. Render every Korean label exactly as written below, in a clean sans-serif
Hangul typeface, set horizontally, in dark navy on white for maximum contrast, at a
generous size so it stays readable when the image is scaled down. Every Hangul syllable
must be a real, correctly formed Korean character. Do not invent, distort, duplicate,
garble or omit characters. Do not translate the labels into English. Do not add any text
that is not listed. Lay the diagram out with enough spacing that no label overlaps
another label or a stroke.
```

**모든 라벨은 원고에 실재하는 문구에서 가져온다.** 그림에 새 용어를 만들면 본문에 없는 내용이 삽화로 들어간다. 원고에 없는 라벨이 필요하다면 그것은 그림의 문제가 아니라 원고의 누락이므로 원고를 먼저 고친다.

라벨 밀도가 높은 도해(표에 가까운 것)는 여전히 표가 낫다. 그림이 이기는 것은 **관계·순서·분기**이지 항목 나열이 아니다.

## 화풍 통일

전체 삽화가 한 문서의 그림처럼 보여야 한다. 그림마다 다른 스타일 지시를 주면 문서 안에서 삽화가 이질적으로 보인다.

**모든 프롬프트에 동일한 스타일 프리픽스를 붙인다.** 프리픽스는 `references/illustration-style.md`에 정의되어 있다. 그림별 차이는 내용 부분에서만 만든다.

프리픽스를 수정해야 하면 **전체 프롬프트를 함께 갱신한다.** 프리픽스만 바꾸고 이미 만든 그림을 그대로 두면 화풍이 섞인다.

## 생성: codex exec

`codex exec`의 내장 `image_generation` 도구를 사용한다. ChatGPT OAuth로 인증되어 있으면 API 키가 불필요하다.

### 사전 점검 (세션당 1회)

```bash
codex --version
codex login status                              # "Logged in" 확인
codex features list | grep image_generation     # 사용 가능 확인
```

미로그인 상태로 N개를 띄우면 N개가 모두 실패한다. 첫 생성 전에 확인한다.

### 단일 생성

```bash
codex exec \
  --sandbox workspace-write \
  --skip-git-repo-check \
  --cd _workspace/images \
  -o /tmp/codex-il-01.md \
  "이미지 생성 도구로 '<프롬프트>' 이미지를 생성하고 ./compliance-process-2026.png 로 저장. 파일 경로만 한 줄로 보고."
```

- `--ask-for-approval`을 붙이면 **에러로 종료한다.** `codex exec`는 비대화형이라 승인 개념이 없다.
- `--skip-git-repo-check`를 빼면 워크스페이스 검증에서 멈춘다.
- 소요 시간은 장당 약 80~110초. 분산이 크다.

### 병렬 생성 (최대 5개)

`codex exec` 각각이 독립 세션이므로 백그라운드로 N개를 띄우면 진짜 병렬이 된다. 5개 동시 시 직렬 대비 약 2.8배 빠르다.

**출력 파일명이 모두 달라야 한다.** 같은 디렉토리에 같은 파일명으로 N개가 쓰면 마지막 것만 남는다.

번들 스크립트가 5개씩 배치를 자동 처리한다. **스펙 파일로 넘겨라** — 프롬프트가 1000자를 넘는 것이 보통이라 셸 배열로 넘기려다 조용히 실패한다.

```bash
# 한 줄에 "<프롬프트>::<출력>.png" 하나씩 담은 파일을 만든 뒤
.claude/skills/guide-illustration/scripts/gen_illustrations.sh \
  _workspace/images --from-file _workspace/07b_gen_args.txt
```

셸 배열로 넘기는 방식이 실패하는 두 가지 경로는 **둘 다 "생성 0건"으로 조용히 끝나므로** 눈치채기 어렵다.

| 함정 | 증상 |
|------|------|
| `mapfile` 사용 | bash 전용 빌트인이다. macOS 기본 셸(zsh)에서 `command not found` 후 인자 0건 |
| `while read` 로 배열 채우기 | 마지막 줄에 개행이 없으면 그 줄을 버린다. `\|\| [ -n "$line" ]` 를 붙여야 한다 |

인자 개수를 스크립트가 보고하므로(`loaded N spec(s)`) 기대한 수와 다르면 즉시 중단하라.

6개 이상을 한 배치로 띄우면 큐잉으로 응답 시간 분산이 커진다. 스크립트가 5개 단위로 나눈다.

`sleep`으로 완료를 기다리지 않는다 — 백그라운드 작업 완료 통지가 자동으로 온다.

## 검수

**이미지 생성은 조용히 실패한다.** codex가 성공 메시지를 내고도 0바이트 파일을 남기는 경우가 있다. 검수 없이 완료 보고하면 빌드 단계에서 깨진 이미지가 발견된다.

```bash
ls -la _workspace/images/*.png
file _workspace/images/*.png     # "PNG image data, WxH" 확인
```

파일 검수는 스크립트가 한다: 파일 존재 / 0바이트 아님 / PNG 시그니처 유효.

**여기서 멈추지 마라. 생성한 그림을 전부 눈으로 열어봐야 한다.** 파일 검수를 통과한 그림도 내용은 틀린다. 실제 20장 전수 확인에서 4건이 걸렸다 — 결정 트리의 말단 하나가 아무 화살표도 못 받았고, 문서 세트는 모든 행에 범례의 배지 4개가 전부 붙어 범례가 무의미해졌고, 개방성 등급표는 칠하기 의미가 범례와 반대로 나왔고, 사다리에는 라벨을 주지 않은 빈 칸 5개가 남았다. 넷 다 파일 검수는 통과했다.

내용 검수 항목:

| 항목 | 무엇을 보는가 |
|------|--------------|
| 한글 | 깨진 음절, 없는 글자, 오탈자 |
| 연결 | 모든 말단이 화살표를 받는가. 교차·끊김이 없는가 |
| 범례 | 범례의 기호가 실제로 구분에 쓰였는가. 모든 항목에 다 붙어 있으면 무의미하다 |
| 빈 요소 | 라벨 없는 빈 상자·빈 태그가 남았는가 |
| 화풍 | 나머지 그림과 선 굵기·채움·글자 크기가 같은가. 파일 크기가 유독 작으면(다른 것의 1/5 이하) 대개 선만 있는 와이어프레임이 나온 것이다 |
| 사실 | 라벨이 원고의 표·목록과 개수까지 일치하는가 |
| 관계 | 그림이 표현하는 **관계**가 원고 서술과 맞는가 — 화살표가 어느 노드에서 어느 노드로 가는지, 담당 주체 밴드가 어느 단계에 걸리는지, 격자 축의 개수가 원고의 판정 변수 개수와 같은지 |

**라벨 검수와 관계 검수는 다른 일이다.** 라벨을 원고에서 가져오는 절차만으로는 관계가 걸러지지 않는다. 외부 리뷰에서 20장을 원고와 대조하니 10장에서 어긋남이 나왔고, 전부 라벨은 원고에 실재하는 문구였다 — `origin` 리모트가 Push 단계가 아니라 동기화 단계에 붙어 있었고, 공개 절차 11단계 중 두 단계의 담당 주체가 원고와 달랐고, 취약점 선별 격자의 축이 원고의 판정 변수 4개 중 3개만 담았고, 라이선스 스펙트럼의 OSI 비승인 목록이 5개 중 3개만 적혀 있었다. 라벨 단위 검수는 이 열 건을 하나도 잡지 못한다.

그림 하나마다 이렇게 확인한다.

1. 원고에서 그 그림이 대응하는 **문단·표를 다시 열어 놓는다**. 기억으로 하지 않는다.
2. 원고에 열거된 항목 수를 센다. 그림의 노드·행·칸·축 개수와 맞추어 본다. 하나라도 다르면 그림이 틀린 것이다.
3. 원고가 **규정하지 않은 관계를 그림이 그리고 있지 않은지** 본다. 원고가 부서별 검토 관점만 서술하는데 그림이 병렬 가능 여부와 선행 의존을 그리면, 그림이 원고에 없는 규범을 만들어 낸 것이다. 이때는 그림을 고치거나 원고에 규정을 넣거나 둘 중 하나를 해야 한다.
4. 그림이 원고보다 축약된 것은 괜찮지만, 축약이 **판정을 바꾸면** 안 된다. 허용형에서 BSD 하나가 빠진 것은 축약이고, OSI 비승인 목록에서 둘이 빠진 것은 독자가 그 둘을 오픈소스로 분류하게 만드는 오류다.

재생성 프롬프트에서는 간선·행·칸을 **하나씩 명시한다**. "격자를 그려라" 수준으로 두면 빈 격자나 범례와 어긋나는 채움이 나온다. `_workspace/build_v3_specs.py` 가 이 방식의 예다 — 16개 칸의 채움 등급을 행 단위로 열거하고, 담당 밴드가 몇 번 단계에 걸리는지 밴드마다 적는다.

**재시도는 1회만.** 실패가 반복되면 프롬프트가 원인이다. 특히 구조가 틀리게 나오면 "다시"가 아니라 **간선을 하나씩 명시**하는 방식으로 프롬프트를 바꾼다(어느 노드의 어느 분기가 어느 말단으로 가는지 전부 쓴다). 화풍이 어긋나면 채움·선 굵기·글자 굵기를 명시적으로 요구한다.

## 배치

검수 통과한 파일을 페이지 번들로 복사한다. **`static/`이 없으므로 페이지 번들 밖의 이미지는 배포되지 않는다.**

```bash
cp _workspace/images/compliance-process-2026.png content/en/using/
```

- 파일명은 소문자·하이픈·영문만. `imgproc`가 확장자 없이 참조한다.
- 기존 파일을 교체할 때는 `-2026` 접미사로 **새 파일을 만든다.** 덮어쓰면 롤백이 불가하고, 개정이 반려되면 원본을 복구할 수 없다.
- 기존 파일 삭제는 원고 반영 시점에 오케스트레이터가 판단한다. 생산 단계에서 지우지 않는다.

원고의 참조와 파일명이 일치해야 빌드가 통과한다:

```bash
grep -noE '\{\{< imgproc [a-zA-Z0-9_-]+' content/en/using/_index.md
ls content/en/using/*.png
```

## 로고는 생성하지 않는다

기업·제품 로고를 이미지 모델로 만들면 실제 상표와 다른 위조 로고가 된다. 원고에 등재된 도구의 제품명이 바뀌어 로고 교체가 필요하면, 생성 대상이 아니라 **공식 로고 확보 대상**으로 분류한다. 공식 로고는 해당 프로젝트·기업의 브랜드 자산 페이지에서 사용 조건을 확인해 받는다.

## 안티패턴

- **라벨 없이 숫자·기호만으로 그리기** — 독자가 본문과 대조해야 하고, 그림과 본문의 불일치가 드러나지 않는다.
- **원고에 없는 라벨을 지어내기** — 검증되지 않은 내용이 삽화로 들어간다.
- **그림별로 다른 스타일 지시** — 화풍이 섞인다. 프리픽스를 고정한다.
- **`codex exec`에 `--ask-for-approval`** — 즉시 에러 종료.
- **포그라운드로 N개 직렬 실행** — 병렬 이득이 사라진다.
- **`sleep` 폴링** — 완료 통지가 자동으로 온다.
- **6개 이상 한 배치** — 큐잉으로 일부 작업이 비정상적으로 길어진다.
- **출력 파일명 충돌** — 마지막 것만 남는다.
- **파일 검수만 하고 완료 보고** — 0바이트는 아니지만 내용이 틀린 그림이 그대로 실린다. 전부 열어봐야 한다.
- **기존 이미지 덮어쓰기** — 롤백 불가.
- **로고 생성** — 위조 상표가 된다.
- **프롬프트에 셸 특수문자(`"`, `` ` ``, `$`) 포함** — 명령 문자열이 깨진다.
